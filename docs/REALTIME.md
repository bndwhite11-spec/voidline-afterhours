# Revision streams and Standard attachments

`GET /api/realtime` uses the native opaque-cookie session and emits Server-Sent Events. Optional `conversation=<native UUID>` or `channel=<community channel UUID>` selects one authorized scope. They are mutually exclusive. Requests from another browser origin are rejected. No identity header, cosmetic badge, public handle or platform-owner label authorizes a conversation.

Frames contain account-bound monotonic revision counters and an optional authorized scope revision. They contain no message text, author/member names, room names, credentials or encryption material. Native/community change triggers and membership/organization mutations update account revision rows atomically with their original writes. Existing records receive no activity backfill in migration 0009. Gifts, social activity and other surfaces retain their separate authorized refresh flows; this feed does not claim to cover every product mutation.

The Worker checks one bounded revision/session/membership query every two seconds, emits a heartbeat after ten quiet seconds and renews after 45 seconds. D1 does not expose a push subscription interface: this is a streamed revision feed driven by server-side database checks, rather than a WebSocket broker. Leases enforce at most five active streams per account across Worker instances. Each loaded page names itself with a random `client` UUID; a tab that reconnects (new conversation, renewal, network change) replaces its own lease, so switching conversations cannot use up the account's slots, and a superseded stream stops reading the database. Leases expire in 45 seconds and are removed after completion/cancellation. Session revocation, expiry, suspension or removal from the selected conversation closes the feed. Stale leases expire even if a runtime cannot propagate a disconnected browser's cancellation immediately.

`hello`, `revision` and `heartbeat` include `seq`, `accountRevision`, `nativeRevision`, `conversationId`, `channelId`, `conversationRevision` and `scope`. `hello` also identifies the lease length and whether the supplied `Last-Event-ID`/`after` differs from current state. `renew` requests reconnection; `restricted` ends access; `unavailable` requests a fallback. `nativeRevision` is an account revision hint for the client, not a native message sequence.

There is no plaintext SSE event log to replay. Resume IDs are hints. The browser reconnects with backoff and fetches missed messages/edits/deletions through the existing authenticated native/community message cursors. Those cursor APIs independently recheck permissions. They remain authoritative for history and acknowledgments. The UI reports live connectivity after parsed stream events, applies a heartbeat watchdog, closes hidden-tab streams and retains polling when streaming fails. Server acceptance remains distinct from delivery or reading.

Controlled verification includes migrated SQLite sessions/ReadableStream frames and actual workerd/D1 streaming: initial frame, committed change frame, and stream termination after session revocation. Hosted proxy streaming, independent-device behavior and browser/mobile rendering require separate verification; source existence alone does not establish those properties.

Standard media uses R2-backed `media_assets` records. `attachmentIds` bind up to four staged assets (8 MiB each, 32 MiB total) into the message's immutable retry hash, including their selected order. A guarded atomic batch verifies uploader, exact conversation/channel, expiry, staged state, kind and size; inserts one stable message; claims its assets; and appends a change. Simultaneous claims cannot give one asset to two messages. The same payload retry returns the existing acknowledgment, including after redaction, without resurrecting content. Metadata serialization preserves selected order.

Every file GET independently checks current account, profile/message visibility and membership. Message deletion immediately hides attachment metadata and queues physical object cleanup. Profile replacement queues only unused previous ready artwork. Cleanup records survive metadata cascades and carry no account foreign key. Temporary suspension hides access while preserving media for reinstatement.

These Standard uploads and messages are service-readable. Matrix encrypted attachments continue through the maintained Rust attachment path; an encrypted send never dispatches to these native endpoints.
