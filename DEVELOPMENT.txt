IDENTITY AND AUTHORIZATION
- Immutable internal account IDs carry authority. Unique normalized handles,
  display names, private verified emails, provider subjects and nicknames are
  separate. @xrp is an owner hint only. First registration grants no privilege.
- New accounts start genuinely empty. Reads must not restore fixtures, fabricate
  unread/activity counts or upload an older device archive. Preserve real data.
- Passwords use pinned maintained Argon2id v19, 19 MiB/two passes/one lane, random
  salts and 32-byte output. Known legacy PBKDF2 records migrate only after a
  successful credential-version CAS. Keep runtime compatibility/load claims
  separate from isolated hash measurements; never downgrade to conceal limits.
- Secure HttpOnly __Host- cookies hold opaque native sessions. Mutations check
  current account/session state, allowed Origin, CSRF and expected account ID.
  Sensitive credential/role/gift changes recheck authorization at commit and
  invalidate access through the appropriate revocation path.
- Google uses maintained server OIDC verification, state/PKCE/nonce and provider
  subject mapping. Email matches do not link accounts or expose provider data.
  Unconfigured Google/mail is unavailable, not a decorative successful button.
- Verified-email reset tokens are hashed, unpredictable, ten-minute and one-use;
  offline recovery codes are distinct possession factors. A provider receipt
  does not establish inbox delivery. Recovery changes, never reveals, passwords.
- Passkeys are maintained signed-in verification, not inferred client MFA flags.
  Owner actions need recent authentication and UV. Protect the final owner key.
  Follow OWNER-BOOTSTRAP.md for trusted one-time immutable-ID binding; community
  ownership cannot become platform administration. No real owner is implied by
  fixture tests or by this release alone.

CORRECTNESS INVARIANTS
- Community created_by is the authoritative owner account. Role rows synchronize
  through a commit-time transfer and database invariants. Ownership revision/CAS,
  eligible target membership and active actor/session checks reject stale writes.
  A unique owner-role index plus triggers prevent independently promoting a second
  owner, deleting/demoting the current owner, or assigning an ineligible target.
- Migration 0008 normalizes duplicate role rows against a valid authoritative
  account and audits previous owner IDs. Broken/ineligible links are quarantined
  for trusted infrastructure review; do not guess a replacement from names or
  silently grant a privileged user. Applied migration SQL remains immutable.
- Native and community messages expose monotonic revisions advanced by database
  change triggers, including edits/deletions/reactions. Read message content and
  related state consistently. Client merges reject older revisions and retain
  tombstones. Do not let delayed initial history bypass the same merge rule.
- Community mentions use immutable account IDs via mentionIds; server membership
  checks and message edits keep mention rows consistent. Display names are only
  presentation. Existing arbitrary @display-name text is not retroactively
  invented into a mention award/notification.
- Native DM sends still check eligible active participants/blocks. In existing
  groups, an inactive or blocked pair does not silence unrelated eligible senders.
  The blocked/suspended account's own permissions remain enforced. A block does
  not cryptographically hide shared-group messages from an authorized member.
- Native group metadata, member addition/removal and ownership transfer require
  the current owner and commit-time eligibility, with atomic audits. A group
  owner must transfer before leaving others; account deletion follows documented
  anonymization/ownership protections. Matrix membership is a separate authority.

MESSAGE, QUERY AND UI CONTRACTS
- Standard messaging is service-readable HTTPS/D1 text with explicit consent.
  Its immutable security mode and identifiers cannot select Matrix rooms or serve
  as encrypted-send fallback. Existing plaintext remains accurately labeled.
- Stable retry IDs bind intended payloads. Pending, server-accepted, failed and
  retrying are separate; delivery/read must not be invented from an HTTP receipt.
  Account/conversation/thread drafts and queues cannot follow a user into a
  different account or destination. Standard tab drafts are not the crypto vault.
- Filter the full authorized account before capturing list snapshot positions.
  Ten-minute account-bound snapshot cursors retain order/filter under new activity;
  every page rechecks current membership. Expiry/filter changes request a fresh
  snapshot rather than silently skipping records. Old offset compatibility is
  not evidence of stable pagination unless a cursor/snapshot is carried through.
- Standard search covers permitted server history with authorized counts/results.
  Native bookmarks sync source references and their own revisions; deletion or
  lost source access cannot be bypassed. Private previews remain respected.
  Encrypted search remains client-side over loaded decrypted data.
- Drain message/change backlogs in bounded cancellable batches with actual
  cursor progress and backoff. Keep message and change cursors distinct and
  commit them after processing. Report catching up without fake real-time status.
- Track viewed messages only when the conversation/document is eligible and
  visible; do not mark the greatest loaded row as viewed. Explicit bulk read is
  separate. Inbox/profile/background opening must not silently acknowledge text.
- Use keyed timeline updates to retain unrelated focus, selection, scroll anchors
  and media. Preserve composition through polls/dialogs, handle IME composition
  and cap input growth. Windowed large-history rendering and physical-device
  screen-reader/keyboard acceptance remain further work.

PROFILE MEDIA
Profile > Edit profile > Upload image or GIF opens the selected Avatar/Banner
flow. Still images retain Canvas cropping and Use this crop; GIFs use Use this GIF
and preserve original bytes/metadata. Centered cover framing changes display,
not the encoded GIF. Both paths stage media; Save profile is the commit action.
Keep stable upload IDs and exact prepared bytes on retry; reject obsolete editor/
account callbacks. Selection/preparing/error/uploaded states are explicit beside
the image tools. Pending or failed selections cannot become a saved status when
generic input/change events run. Keep confirmation and Save actions visible in
short tablet dialogs as well as narrow phones. Native file-event tests dispatch
all registered listeners; the DOM harness must not replace earlier callbacks.

Only the profile source path opts into allowProfileJpegTrailing. It uses sourceEnd
to slice a complete primary JPEG before native decoding, including progressive
scans and length-delimited metadata. Server uploads do not opt in. Extra camera
data is never uploaded by the still crop; keep strict default validation and
truncated-source rejection covered separately.

All files have an 8 MiB bound. Profile GIF limits combine 1024 pixels per side,
one megapixel per canvas, 200 frames, 32 megapixels across frame canvases and a
30-second loop. Shared validation is browser structural preflight; the server
decodes every GIF frame and creates a protected static first-frame PNG preview.
Do not flatten a GIF through Canvas or claim its metadata has been stripped.

The canonical /api/media/:id URL serves a GIF's static PNG preview for old and
current inline-avatar clients. Only /api/media/:id/animation serves the original;
both use the same current profile/block authorization. Play GIFs/Pause GIFs are
explicit profile-card controls. Reduced motion, hidden/closed profiles and
account changes stop playback. Uploads do not autoplay. New GIF staging enables
Allow GIF playback and profile effects in the draft; the owner can clear it.
Controlled DOM tests establish state/lifecycle behavior, not actual browser GIF
decoding, native pickers or physical-device playback.

ENCRYPTED PATH
Matrix SDK 45.1.0 / Rust crypto WASM 18.9.2 are the maintained protocol. Do not
invent a cipher protocol, embed a shared content key, weaken verified-device
checks or copy standard history into protected rooms silently. Normal configured
Synapse enrollment maps immutable IDs to a reserved namespace and validates
whoami/user/device before opening a dedicated encrypted store. A native password
plus persistent client seed derives local unlock material. Raw credentials never
enter ordinary localStorage; the token envelope is authenticated-encrypted.
Advanced manual token entry remains separate. Read ENCRYPTED-SETUP.md before
setting provider secrets or assuming a public Matrix account is compatible.

Keep encrypted intended outbox writes durable before SDK send. Payload conflicts
fail. An unconfirmed retry needs its original Matrix token/session; do not create
a new transaction under a rotated token and pretend deduplication is preserved.
Rust v2 attachment encryption protects contents before upload; key/name/descriptors
travel inside encrypted messages. Fetch media with Authorization, size/type
limits and no URL credentials; revoke decrypted Blob URLs after their view ends.
Microphone permission is deliberate, late tracks are stopped and cancellation
must not attach a recording to a new conversation. Native Standard media remains
service-readable and separate from this encrypted path.

Invitations preview without joining, validate encryption after deliberate accept
and distinguish invitation state from verified identity. Leave/removal/cancel
use actual Matrix membership and powers; SDK/history limits remain explicit.
Recovery journals encrypt resumable client state, preserve existing keys/backups
and retain only sanitized public signing payloads for UIA retry. Automatic backup
version deletion is blocked at final dispatch. Backup-enabled is not proof of
restore; verification markers bind the actual restored key ID/backup version.
Logout locks locally first and reports confirmed/failed/unknown remote outcome.
Never persist raw-token retry queues or native passwords as Matrix UIA passwords.

No homeserver/live multi-device acceptance is configured. JWT-only Synapse UIA
can be insufficient for device deletion/key reset; report unsupported service
authentication and preserve state rather than manufacturing success. Native
suspension/blocks/community changes are not atomic remote Matrix revocation.
Encrypted-by-default readiness remains false until service, policy, invitations,
keys, attachments and recovery pass actual multi-device acceptance. Calls, full
crypto search indexes, cross-service media retention and complete moderation are
separate engineering, not solved by a configuration field.

SAVED AND NOTIFICATIONS
Saved exposes distinct storage/security scopes: synced authorized Standard source
bookmarks, encrypted self-only Matrix Saved and local encrypted notes. The local
vault uses PBKDF2-HMAC-SHA256/600,000 and AES-256-GCM with fresh IVs and authenticated
record/account namespaces. Its separate passphrase is not restored by account
login or Matrix backup. Stored metadata/counts and offline guessing remain risks;
unlocked browser/XSS/extension compromise can read available plaintext.

Generic native Web Push uses maintained WebCrypto-compatible delivery code and
provider-configured server VAPID keys. Browser enrollment is deliberate. Queueing
or a push-provider receipt is not device-display evidence. Payloads exclude
message text; preferences, mute/quiet hours, current access/session and deduplication
are enforced. Matrix push and real browser delivery require separate verification.
Do not create notification permissions, socket states or presence events as mocks
in the production experience. See root delivery-status notes for current rollout.

D1 MUTATION ACKNOWLEDGMENTS
D1 result.meta.changes includes writes performed by database triggers. SQLite's
SQL changes() and node:sqlite statement.run().changes count the direct statement.
For a uniquely targeted conditional mutation, a positive D1 metadata count proves
the guarded row matched; requiring exactly one can falsely reject a committed
owner transfer, message edit or group leave. Keep direct SQL changes()=1 checks
inside transactional audit gates. Do not broadly replace permission predicates.
backend/d1-runtime-test.mjs runs actual native/community handlers with workerd D1,
including trigger-inclusive acknowledgments and denial cases. It is backend
runtime proof, not browser or real Matrix acceptance.
